# Release Notes — v0.0.8 (2026-10-11)

## ✨ New Features

- **Config key type collision detection**: Konfigo now rejects configurations where the same config key is declared by several config groups with different value types (e.g. `Number` in one group and `String` in another). Previously such conflicts went unnoticed and could lead to unpredictable values at runtime.
  - **Backend (gRPC)**: `RealtimeConfigGrpcService` validates incoming `CreateVersion` requests and fails with `InvalidArgument`, listing every conflicting key, its types, and the groups that declare them.
  - **.NET SDK**: Discovery of `[ConfigGroup]` classes now runs `ClassDefinitionsValidator` and throws the new `ConfigKeyCollisionException` (exposes a `Collisions` collection). Definition discovery is now lazy, so the exception surfaces on first use rather than inside a static constructor (no more `TypeInitializationException` wrapping).
  - **Go SDK**: `DiscoverDefinitions` returns a new `*ConfigKeyCollisionError`; the check is also available standalone via `ValidateDefinitions`.
  - **Python SDK**: `discover_definitions` raises the new `ConfigKeyCollisionError` (a `ValueError` subclass); the check is also exported as `validate_definitions`.

## ⚠️ Behavior Changes

- Services that previously declared the same key with different types across groups will now fail at startup (SDK-side) or on version creation (server-side). Align the key's type across all groups, or rename one of the keys, before upgrading.

## 🧪 Tests

- Added coverage for collision detection in the gRPC service, .NET, Go, and Python SDKs.
- Integration tests for service creation/update now use `example.com` email addresses.

## 📦 Other

- Version bumped to `0.0.8` across `VERSION`, `Version.props`, backend/frontend project files, SDK packages, and documentation.
